ZOHO DESK — UI, MODULE &amp; API REFERENCE
1. Scope and Design Rules
This document is the module-wise UI reference for the Zoho Desk. It uses the supplied public API reference, captured internal UI/API reference, and existing table configuration as the source baseline. Advanced Analytics is intentionally excluded.
UI is organized by module and sub-module; every screen has an API contract and primary database mapping.
The Zoho Desk uses its own versioned REST API and database; Zoho internal supportapi paths are treated as behavioral evidence, not as the Zoho Desk backend.
Every request is tenant-scoped from the authenticated session; Org_Id is never trusted from the client.
Write endpoints require CSRF protection and should use optimistic concurrency for mutable resources.
Dashboard widgets execute validated query definitions; clients never submit arbitrary SQL.
2. Agent Login — Verified Zoho Methodology
Zoho's agent model uses the agent's official email address as the login identity. Agents are invited to Zoho Desk and use the associated Zoho account; enterprise directory/SSO options can also be used. Zoho's official documentation describes Active Directory SSO through Zoho Directory Sync for agents. The captured Desk UI then operates with a web session: the internal supportapi requests use session-cookie authentication plus x-zcsrf-token.
Zoho Desk implementation decision:
Do not add Password or Password_Hash to HD_AGENT_MASTER.
HD_AGENT_MASTER stores the Desk agent identity, role, profile and organizational membership.
HD_AGENT_AUTH stores the external identity-provider mapping (provider + stable subject + login email).
HD_AGENT_SESSION stores server-side session state and CSRF binding.
HD_AUTH_LOGIN_EVENT stores security audit events.
The browser receives an HttpOnly/Secure session cookie; state-changing requests also send a CSRF token/header.
Source verification: Zoho official agent-management documentation states that the official email address is used to log in; Zoho also documents Active Directory SSO for agents. The supplied internal capture confirms the authenticated Desk UI uses session cookie + x-zcsrf-token.
Official references: https://help.zoho.com/portal/en/kb/desk/user-management-and-security/agents-and-teams/articles/add-manage-desk-agents ; https://help.zoho.com/portal/en/kb/desk/user-management-and-security/data-security/articles/configuring-active-directory-sso-for-zoho-desk-agents

11. Global API Response Contracts
List response:
{"data":[...],"paging":{"limit":50,"nextCursor":"...","hasMore":true}}
Single-resource response:
{"data":{...}}
Error response:
{"error":{"code":"TICKET_NOT_FOUND","message":"Ticket was not found","details":{},"traceId":"..."}}
All write endpoints should return the updated resource or a deterministic operation result and should emit an audit/history record where the action changes business state.
12. Implementation Priority
Phase 1: Login, identity mapping, session, CSRF, /me and authorization.
Phase 2: Tickets — All Cases, Agent Queue, Team Queue, Ticket Detail and conversations.
Phase 3: Contacts, Accounts, Agents, Departments and Teams.
Phase 4: Analytics dashboard shell + component query/data execution + access control.
Phase 5: Reports, configuration and automation.
Phase 6: Channels, activities, products/contracts and remaining settings.
13. Source Notes
External verification used for agent authentication: Zoho Desk official documentation for adding/managing agents and Active Directory SSO for agents. The supplied internal UI reference is the source for the session-cookie + x-zcsrf-token behavior.
